# ATOM-only native object builder

2026-09-05. Based on bootstrap checkpoint `d08a900` on `range-and-bootstrap`.
This is a toolchain migration checkpoint, not a published release.

## Implementation

`buildNativeObjectHarness()` now executes the checked ATOM core over its linked
source. It returns the same resident binary and census through the existing
builder API. The AZM compiler, translation, temporary files and static-analysis
invocation are removed. The optional AZM peer dependency is also removed;
remaining historical development tests still require migration.

The linked source is split between complete lines into ordered parts of at most
65,535 bytes. The D8 map is generated by ATOM and identifies those source parts,
rather than an AZM temporary file. The private adapter label `.RANGEFAIL` was
shortened to `.RNGFAIL` to satisfy ATOM's eight-character limit. No instruction
or data declaration changed.

Separate workspace placement preserves the existing addresses. When workspace
is below the code image, its declarations precede the code so IMAGE output is
ascending. Eight literal size equates move ahead of that workspace; the builder
checks their presence and literal form. With workspace above code, the existing
order remains valid. The existing overlap, one-bank and size checks remain.

Register annotations are comments under ATOM. The builder rejects a supplied
`registerContractsProfile` or nonempty `registerContractsInterfaces` instead of
ignoring a request for unsupported analysis. Source fragments must use ATOM
syntax. These build-interface changes are documented in the public API appendix
and declaration file; they do not change the guest service ABI.

## Evidence

The new guarded object-bootstrap test first failed on the AZM import. During
migration, native parsing exposed the overlength label, and three existing
relocation tests rejected descending IMAGE records. The label and source-order
changes above resolved those failures without changing expected guest outputs.

- Guarded `generate-native-object-harness.mjs --check` reproduced the exact
  checked binary and complete census, leaving both files unchanged.
- Guarded `npm run build:native-object` also passed. A tracked diff confirmed
  that the native core, object binary and object census remained unchanged.
- Ten object-harness tests passed, including separate read-only code placement,
  a custom source-reader entry, postlude accounting, workspace limits, 255-part
  input and poisoned-output recovery. A new eleventh test passed with workspace
  above code, exact generated bytes, closed handles and unchanged resident code.
- Eight architecture, documentation and product-reference checks passed.
- The builder declaration file passed a TypeScript no-emit check. Triptych's
  guarded `npm run check` also passed with its unchanged published ATOM pin;
  that consumer result does not qualify this unpublished builder revision.

The final combined run passed all 12 tests with AZM imports blocked:

```sh
node --test --test-concurrency=1 \
  test/host-object-bootstrap.test.mjs test/native-object-harness.test.mjs
```

The default resident extent remains 13,515 bytes, including the existing
12,396-byte core account and 1,119-byte adapter delta. Its SHA-256 remains
`636b1f8d24fc72e574923fcf99729d0ae103756802fa435952d59165769b0fa3`.
Separate placement produces 12,774 code/table bytes and 741 fixed-workspace
bytes (714 core, 27 adapter), plus the caller-owned 399-byte service workspace.
The existing 256-byte prelude gap produces a 13,030-byte code image.

No AZM assembly or static register analysis was performed. CP/M generation,
output-candidate measurements, historical differential tests and the dependency
gate still require migration before a complete ATOM-only release check. The
`$FFFF` output-range issue and Nucleus reconciliation remain open. Downstream
pins are unchanged; package publication, hardware tests and Pages deployment
were not performed.
